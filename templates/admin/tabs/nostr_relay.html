Built-in Nostr Relay (Web of Trust)
The built-in relay is this app's datastore (settings, users, bots, chats all live in its event store), so it always runs — there is no on/off toggle. It serves NIP-01 in its own thread at /relay on the port below, only accepts/syncs notes from a web of trust, and should be fronted with TLS (e.g. wss://relay.yourdomain/).

Web of Trust
On: publishing is gated to the trust set, and the relay runs the trust-graph build, metadata backfill, firehose sync, and NIP-05 serving. Off (e.g. a processing node whose relay is internal): publishing is open and all of that background/cross-node work stops — the relay is a pure local store. Restart after changing.

Distributed compute — share machines over Nostr
When on, this node joins a shared cluster with the peers below: it runs AI jobs (chat / image / music / video) THEY send over Nostr, and it offloads ITS OWN jobs to THEM (round-robin across itself + peers). Your own users are unaffected — this node still serves them locally / via the IP LB; sharing only adds peer capacity both ways. Restart to apply.
One peer per line: their npub + the relay URL to reach them on (space-separated). Sharing is MUTUAL — if you list a peer, they may use your GPU AND you may use theirs. Blank = no sharing. This is GPU-access trust, separate from the social Web of Trust above (a follow does NOT grant access), and you do NOT need to add them to the seeds — the relay auto-accepts a listed peer's compute jobs. (npub-only, no relay = they can use you, but you can't reach them.) Restart to apply.
image/music/video results are too big for a Nostr event (256KB cap), so the worker uploads the bytes to a shared Blossom server and only the hash travels over Nostr. Blank = this node's Blossom Public URL. Every node must reach ONE Blossom server.

Point this at a relay you run (your other node), not at a public one. The bodies are ciphertext and nobody else can read them — but every event carries the author's pubkey, a stable id and a timestamp, so a copy on someone else's relay is a permanent public record of how many passwords each user has and when each one changed, and there is no taking it back. On your own relay that record is already yours. Restart after turning this on.

Auto-clean (feed retention)

The relay store is PostgreSQL — it tunes its own buffers/WAL, so there are no SQLite cache/mmap/DB-path knobs. Auto-clean only ever trims high-volume feed content (notes/reactions/reposts/comments); profiles, contacts, articles, DMs, and your local users' own events are kept forever.

Deletes old notes/reactions/reposts/comments past this age. Set 0 to disable age-based cleanup.
Trims the oldest feed events once the total exceeds this count (preserved events don't count). 0 = unlimited (the age cleaner above is then the only cleanup).
Auto-clean runs on a schedule (shortly after each relay start, then daily). Use Preview to count what the settings above would delete — do that first, it can be hundreds of thousands of notes — then Run to apply it now. Save your changes before either; both read the saved settings.
Pay to stay (paid retention tier)

Everything a visitor publishes to this relay is currently kept forever. Turn this on to age out those posts after a free window, and let an author keep them longer by zapping this relay's profile. Your own users are never affected — accounts on this instance, NIP-05 holders, operators and bridged puppets are in the preserve set and no age rule can touch them. Profiles, contacts, DMs and articles are never auto-deleted for anyone.

Master switch. Off = nothing below has any effect and the prune behaves exactly as it does today.
This is the setting that deletes things. 0 = keep forever (the default, and what happens today) — nothing is ever deleted until you put a number here. Preview the auto-clean above after changing it.
0 = kept forever while subscribed. When a subscription lapses the free window applies again, so a lapsed author's older posts go on the next auto-clean. A subscriber is also exempt from the feed auto-clean and the count cap above — otherwise a copy of their note that reached us over the firehose, rather than being published here, would still be deleted at the feed retention window. Moderation (blocked words/languages/pubkeys) is not exempt: paying doesn't buy immunity from the block purge.
