Video Generation (Wan2.1 — native diffusers)

Text-to-video runs natively in-process on this box's GPU (like image generation, not a separate server), so it shares the same GPU lock and VRAM model-swap: chat, image, music and video all queue as one GPU task at a time. Works on NVIDIA (CUDA), Intel Arc (XPU) and AMD (ROCm). Available in the web UI and Telegram via videogeni <prompt> [| negative]. Arc 16 GB is memory-tight — keep frames/resolution modest there.

Off by default. When off, videogeni returns a friendly notice.

HF id or local path of the diffusers text-to-video model. Default Wan-AI/Wan2.1-T2V-1.3B-Diffusers (~27 GB, fits a 12–16 GB GPU). Stay on stock diffusers (Wan/LTX/CogVideoX) for Arc/ROCm portability — no fp8/GGUF.
Output
Multiple of 16. Wan2.1-1.3B is a 480p model — 832×480 is its native resolution. Generating higher natively risks OOM and looks worse.
Multiple of 16.
Lanczos-upscales the finished clip to this height — cheap, no extra VRAM. The 1.3B model only renders ~480p natively, so this is how you get a 720p/1080p file. For TRUE native detail at 720p you'd need the Wan 14B model (much more VRAM).
Wan uses 4k+1 (e.g. 33, 49, 81). Clip length = frames ÷ fps. Hard max ~81 (≈5s) — the model can't do more and 16 GB OOMs above it.
Max time to wait for a clip to render.
Output & Watermark

Each clip is delivered as a branded MP4 with the same end-card outro (the "watermark") used on effect/music videos.

When off, the clip is delivered with no end-card.
