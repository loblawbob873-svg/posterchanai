Load Balancing — IP-based (legacy)
Comma-separated node IPs (the posterchanai port is assumed). This one list load-balances all GPU work — chat, image, music and video — round-robin between this server and the listed nodes (each node frees its own GPU first). Full URLs (e.g. http://localhost:3052) accepted for non-default ports.
🛰️ Distributed AI over Nostr is the newer way to do this — it dispatches GPU jobs to a Web-of-Trust cluster over Nostr (encrypted, no IPs to manage) and replaces this IP list when enabled. Configure it in Admin → Relay → “Distributed compute (DVM load balancing)”.
SSH Terminal
A real interactive shell in the client (sidebar → Terminal, and its own window in desktop mode). This is a second remote-execution path and a wider one than node management below: that reaches nodes you registered, over Nostr; this reaches any host you list here. ⚠️ A full PTY on the hosts below, running as whatever user you configure. Off by default — only enable on a deployment you trust.
One per line: name  user@host[:port]  [key=/path/to/private_key]. This is an allowlist — the client picks a name and can never name an address of its own, so the terminal cannot be used to reach machines you did not list. No password is ever stored: a host either names a private key file that already exists on this server, or the person types a password that is used for that session and then forgotten.
Who may open a terminal, one per line or comma-separated. Admins are always allowed. Leave empty to keep it admin-only.
Runs your shell inside tmux new-session -A (or screen -xRR) on the far end, so the session survives a reboot of this server too. Nothing is installed for you — if neither is present you simply get a normal login shell, and the keeper below still covers deploys.
Sessions last until you kill them. A dropped connection reattaches; closing the app leaves the shell running; a session opened on one device can be picked up on another. These three limits are off unless you set them — leave them blank unless you have a reason. To let shells outlive a deploy of this app, install the keeper unit: scripts/install_services.sh (it adds posterchanai-shell.service). Without it the terminal works exactly the same, but every session ends when the app restarts.
Agentic Node Management
Run OS commands and agentic tasks (LLM-driven, multi-step goals) on SSH-reachable nodes or local — from chat, Telegram, or the health report. Run OS commands on configured nodes from chat/Telegram (node <name> <cmd>, node agent <name> <goal>). ⚠️ This is unrestricted command execution — only enable on a trusted, private deployment.
Nostr npubs allowed to use this feature — one per line or comma-separated (hex pubkeys / nprofiles also accepted). The first user to sign up (the admin) is always allowed, so their own key is the default.
Max tool-call iterations in agentic mode. Real tasks need dozens; the agent trims its own transcript, so this is no longer bounded by the model's context.
Transient agent artifacts — the /workspace backups produced by a sandbox run — auto-expire from Blossom after this many days, so a run-every-time auto-archive can't fill storage. 0 = keep forever. Chat-generated images/files are not affected.
Roughly 4 characters per token. Once the run's transcript exceeds this, old tool output is shrunk to one line and the oldest steps are dropped. Lower it for a node with a small context window.
Kill a job after this many seconds. 0 = no timeout (use node kill <id>).
Kill a single command inside node agent after this many seconds (0 = use the job timeout above). The agent waits for each command, so this is what stops one hung command deadlocking the run. It had no field here at all, which mattered the day a command that takes 10m22s met the old 600s default: the operator's obvious fix was invisible.
🛰️ Nostr transport. A command is an encrypted NIP-90 event addressed to a worker node's npub (via the built-in relay / DVM). The worker runs it locally and returns an encrypted result — no keys or open ports, works through NAT. Full PosterChanAI nodes (nas, server1) act as workers directly; router.lan / other machines run the lightweight standalone agent (agent/install-agent.sh). local always runs on this host directly. Turn this ON to make THIS host accept commands from its trusted controllers.
One per line: name npub1…. The panel/commands address a worker by name; the command event is sent to its npub. This is the node registry — every remote node is listed here (plus the synthetic local).
⚠️ A DEDICATED allowlist (separate from the shared-compute DVM peers). This host will execute commands ONLY from these signature-verified npubs. Running commands is a bigger grant than GPU-offload, so keep this tight.
🐳 Per-user Debian sandbox. Lets non-admin AI users (and admins who opt in) run agentic tasks confined to their own throwaway Debian container — the agent can do anything inside it without touching the host. One container per user, created on demand, torn down when an agent run finishes, and idle-reaped. Needs Docker on the host + the service user in the docker group. Pin all sandbox/agentic runs to ONE node so agentic GPU work funnels through a single worker instead of competing across the fleet. Enter a node name from the worker list above (e.g. nas.lan); leave blank to run every sandbox on this host. When set to a full peer node, the whole run (container + agent loop) is dispatched there over the Nostr transport, and that worker's own 1-at-a-time agent lock queues concurrent runs. (Replaces the old deterministic container load-balancer.)
Docker image for each user's container. Default: debian:stable-slim.
The container itself is thrown away when a run finishes. This mounts a per-user Docker volume at /workspace that survives, so an agent can keep a checkout, scripts and results between runs. Off = every run starts on bare Debian with nothing. Volumes are named pcai-ws-<user> and are never deleted automatically — prune them yourself if disk matters.
bridge = internet (so the agent can apt install tools); none = fully isolated. The container can't reach the host either way.
Per-container memory cap (docker --memory). Default: 1g.
Per-container CPU cap (docker --cpus). Default: 1.
Per-container task cap (docker --pids-limit). Counts threads, not processes — ./test.sh in a sandbox runs six headless browsers at once and peaks around 800. Too low and every browser check dies with can't start new thread, which reads as a broken test suite. Default: 4096.
System Health Report (Schedulers)
🩺 Runs an agentic health check on each node (disks, SMART, RAID, failed services, recent errors) and files the report in the "Logs" conversation + Telegram (admin only). Requires Agentic Node Management above to be enabled.
Hours to run (comma-separated, 24h format). Default: 1,12,18
Leave empty to check every node (all Agentic Node Management nodes). Only fill this in to narrow the report to specific node names.
Note: Restart the service after changing scheduler settings.
Uptime Monitoring
📡 Polls the endpoints below and shows them in Discover → Server Stats → Uptime (heartbeats, response time, 24h/30d uptime), and on a standalone public status page at /status (JSON at /status.json) that needs no account and no JavaScript. Checks run in the background worker process; state is stored in the Nostr relay, not a database table. Both pages are public — only list endpoints you're happy to publish.
After saving, allow up to ~2 minutes before the first results appear: the checks run in the background worker, which picks up settings changes on its own re-hydrate cycle. No restart needed. Format: Name | URL | interval seconds | expected text. Only the URL is required — a bare URL line names itself after the host. The interval falls back to the default below; with an expected text field the response body must contain it, otherwise any 2xx/3xx counts as up. Lines starting with # are ignored. Renaming a monitor starts its history over (the name is its id); changing its URL keeps it.
Used by any endpoint that doesn't set its own. Minimum 20s.
Consecutive failed checks before a monitor is called down and an alert is sent — stops a single blip from paging you.
Sends 🔴 DOWN / 🟢 UP messages to the admin's Telegram (needs Telegram enabled on the admin account).
Sends the same message as an encrypted NIP-17 DM from this instance's operator key — it arrives in any Nostr client, not just this one.
Who receives the Nostr alerts — one npub per line or comma-separated. Leave empty to DM the admin.
