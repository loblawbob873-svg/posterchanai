🔴 OBS Streaming
Lets users stream from OBS: they publish RTMP here and it appears under Discover → Streams (NIP-53). The MediaMTX binary ships with the install/image; just forward TCP 1935 to this server and tick this box — the app supervises it automatically (no restart needed).
The host OBS pushes to (shown to users in the Go Live dialog as rtmp://<this>:1935). Blank = the server's public IP.
Blank = the app reverse-proxies HLS over your existing tunnel (zero-config, fine for a handful of viewers). For many viewers, point a grey-clouded subdomain at the HLS port (8888) and set it here.
OBS ingest port — forward this on your router.
On by default, and you almost certainly want it on. Without it the media server is a pure pass-through: whatever a streamer's OBS sends is what every viewer downloads, so one person streaming 1080p60 at 6 Mbps costs 6 Mbps of your upload per viewer. With it on, each stream is re-encoded down to the ceiling below and viewers only ever get that — a streamer's settings can't run up your bandwidth bill. The transcode runs on the GPU's video engine, which is separate silicon from the part that runs the AI models, so it doesn't slow chat or image generation down. Toggling this restarts the media server (drops any live stream briefly).
Max height, max frame rate, video bitrate, audio bitrate. Defaults are 720 / 30 / 1500k / 128k — roughly 1.6 Mbps per viewer, so a 20 Mbps upload carries about a dozen at once. A stream that's already below a limit is left alone (a 480p phone stream is never upscaled). Video bitrate is the number that matters: halve it and you double how many people can watch.
Blank auto-detects this node's hardware (NVIDIA NVENC, then Intel/AMD VAAPI, then CPU). Only set this to pin a specific ffmpeg encoder. If the hardware encoder fails to start, the clamp falls back to CPU on its own — check journalctl for clamp: lines.
Global switch. Each streamer also opts in per-stream (Go Live → “Save my streams”). A recorded stream is written to a temp dir, then uploaded to the streamer's Blossom drive when it ends and shown under their profile → Streams. Toggling this restarts the media server (drops any live stream briefly).
Where MediaMTX writes recordings before upload. It's just a path — mount it as tmpfs (or point it at /dev/shm) if you want RAM-backed recording with no SSD writes.
