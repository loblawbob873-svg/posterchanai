Local Monero tip wallet

Loopback Wallet RPC and small balances only. Choose stagenet for testing or explicitly select mainnet for real funds. Wallet seeds and spend keys never enter PosterChan.

Only an explicit numeric loopback or private RFC1918 address is accepted—such as http://192.168.0.85:38083/json_rpc. Hostnames and public RPC servers are refused.

MAINNET is a hot wallet. Keep only small tipping funds here; retain substantial Monero in Feather, Monero GUI, or hardware storage.

Multi-chain wallet (Exodus)

This node holds the keys. Turning this on means the server generates and stores a BIP-39 seed for every user who opens the wallet, encrypted at rest with their storage key. That is custody: their Bitcoin, Ethereum and the rest are recoverable only from this machine's keystore and database. Leave it off unless you intend to be responsible for that. Monero is deliberately excluded — this node already runs a real Monero wallet above, and a second XMR key would give one person two balances.

Where each chain is read from. Leave a field blank to use a public endpoint — a fallback, not a plan: those rate-limit, they see every address you look up, and they can disagree with the chain. A node that matters points at its own. Balances are read through this server's outgoing proxy, so a lookup does not announce your users' addresses from the app server directly. Nothing here can move money; sending is a separate path.

Zap service fee

A cut of each zap sent through a wallet this node holds, paid to you. It applies ONLY where this node executes the transfer — a zap paid from the user's own wallet through the address/QR flow never touches this server, so there is nothing to take a cut of. The cut comes out of the amount, so the sender is debited exactly what they typed and the recipient receives the remainder. A cut smaller than 0.00001 XMR is skipped: the extra output would cost more in transaction size than it earns.
