Music Generation (ACE-Step)

ACE-Step needs its own Python 3.11–3.12 environment, so it runs as a separate service (the acestep-api REST server) and PosterChanAI talks to it over HTTP — like the Budget Manager and the external image servers. Start it with install.sh (option) or the Docker acestep service, then point the URL below at it. Generation is available in the web UI and Telegram via musicgeni <style prompt> [| lyrics].

Off by default. When off, musicgeni returns a friendly notice.
The local acestep-api server (shares this box's GPU). Requests to it take the shared GPU lock and swap the LLM/image model out of VRAM first — one GPU task at a time, exactly like image generation.
Optional comma-separated ACE-Step servers on OTHER nodes. Tried round-robin (no local GPU lock); falls back to the local server above. Same pattern as Image Server URLs.
Which lock the local server uses (GPU vs CPU). Set CPU only if the local ACE-Step runs on CPU, so it doesn't needlessly block GPU chat/image.
DiT model name/path passed to the server (e.g. acestep-v15-turbo for fast 8-step generation, acestep-v15-base for quality). Fits a 12 GB GPU. Leave empty to use the server's default.
Turbo ≈ 8; base up to ~200 (slower, higher quality).
Max time to wait for a song to render.
Output & Watermark

Each song is delivered as a branded video: the song plays over a generic PosterChan background, then the branded end-card outro (the same "watermark" used on effect videos) is appended.

When off, the song video has the background but no end-card.
