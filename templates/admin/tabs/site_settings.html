Appearance
Theme applied to /client for any visitor/device that hasn't picked their own theme in User Settings. A logged-in user's saved theme always wins.
Replaces the built-in PosterChan logo in the web client's favicon, login splash and header. Use a square PNG for best results. Leave blank for the default logo.
Instance custom emoji moved to its own tab — see Admin → Emoji.
Sign in with an account (login page) Extra buttons on the web client's login screen, for people who don't want to manage a Nostr key. Both are off by default: they are the only routes where an identity is created by this server rather than in the visitor's browser. Everything else on that screen (extension, remote signer, pasted nsec) keeps the key on the device and is unaffected.
Sign in with a fediverse account. The OAuth app is registered on the instance automatically (public /api/v1/apps) — nothing to configure on their side. A visitor whose account is already linked here (Fediverse bridge / User Settings → Social) is signed in as that same account, not a new one.
Pre-filled on the login form; the visitor can type a different one. Blank = the Read Account instance from Admin → Social.
Needs an OAuth 2.0 Web application client from the Google Cloud console:
1. APIs & Services → OAuth consent screen → External, add the openid, email and profile scopes, then publish it (or add testers).
2. Credentials → Create credentials → OAuth client ID → Web application.
3. Authorised JavaScript origin: this node's public origin (e.g. https://poster.place).
4. Authorised redirect URI, exactly: <public base>/api/auth/google/callback.
5. Paste the client ID and secret below and Save.
Stored like every other setting: in this node's operator-signed relay document, NIP-44 encrypted — never in the repo or a config file.
