Load Balancing — IP-based (legacy)
Comma-separated node IPs (the posterchanai port is assumed). This one list load-balances all GPU work — chat, image, music and video — round-robin between this server and the listed nodes (each node frees its own GPU first). Full URLs (e.g. http://localhost:3052) accepted for non-default ports.
🛰️ Distributed AI over Nostr is the newer way to do this — it dispatches GPU jobs to a Web-of-Trust cluster over Nostr (encrypted, no IPs to manage) and replaces this IP list when enabled. Configure it in Admin → Relay → “Distributed compute (DVM load balancing)”.

ℹ️ Load-balanced storage

For load-balanced setups, set Storage Server URL to proxy file requests to a designated storage node. This avoids requiring a shared filesystem (NFS) — one node handles storage, the others proxy requests to it.

Setup:
• Storage node: leave storage_server_url empty, set upload_path to a local directory
• Client nodes: set storage_server_url to the storage node (e.g. 192.168.0.10)

Onion Site (.onion)
Expose this deployment over Tor at a persistent .onion address (requires the Managed Tor Service above). One click generates it and applies it live — no restart. The address survives restarts (Tor keys persist in the data dir).
Second Tor Daemon (load-balancing)
Runs a second tor instance with its own circuit/exit IP (only when Auto-start Tor above is on). The built-in HTTP proxy round-robins across both — exit-IP diversity that dodges per-IP rate limits and geo-blocks. Torrent traffic stays Tor-only (never falls back to direct).
Use a different region than the first daemon for diversity. Default: Canada ({ca}) — geographically close, so minimal latency cost.
